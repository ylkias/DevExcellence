# Security policy

Do not publish exploit details for an unpatched vulnerability in a public issue.

When reporting a security concern, include the affected version/commit, impact, safe reproduction steps in an authorized environment, and a suggested mitigation. Do not submit credentials, personal data, production dumps, or sensitive customer information.

DevExcellence provides engineering guidance and does not guarantee that software is vulnerability-free. It is not a substitute for an organization's security program, independent testing, or professional review.

Only test systems for which you have explicit authorization and a defined scope.
