# Code quality and completeness checklist

- [ ] Request, requirements, and acceptance criteria are understood.
- [ ] Existing architecture and project conventions are followed.
- [ ] No incomplete branches, functions, workflows, or state transitions remain.
- [ ] No fake success response or production placeholder remains.
- [ ] Dead, unreachable, obsolete, and unused code was investigated safely.
- [ ] Duplicate logic and unnecessary abstractions were evaluated.
- [ ] Errors, edge cases, empty states, and cancellation are handled.
- [ ] Resource lifecycle and cleanup are correct on success and failure.
- [ ] Names, boundaries, and responsibilities are understandable.
- [ ] Tests cover important behavior and negative paths.
- [ ] Documentation reflects behavior changes.
- [ ] Final diff contains no unrelated changes or debug artifacts.
