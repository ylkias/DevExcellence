# Contributing to DevExcellence

Thank you for helping improve the skill.

## Contribution principles

- Preserve the core purpose: a useful, portable skill that improves software delivery.
- Keep core guidance provider-neutral and stack-agnostic.
- Prefer concise, actionable instructions over generic advice.
- Do not add mandatory ceremony or dependencies without clear value.
- Add examples and validation criteria for new rules.
- Distinguish requirements from optional recommendations.
- Never include proprietary source code, credentials, production data, or private vulnerability details.

## Changes

1. Open an issue or explain the problem in the pull request.
2. Describe the intended developer value and affected workflow.
3. Update relevant checklists, docs, and templates.
4. Include reproducible examples or tests when practical.
5. Explain trade-offs, limitations, and host-specific assumptions.

## Review standard

Contributions should be clear, evidence-based, safe, and compatible with a single-agent workflow. Multi-agent features must remain optional. No change should claim that a scan or test passed without actual evidence.
